# 코드 리뷰 가이드

## 코멘트 태그
| 태그 | 의미 | 작성자가 할 일 |
|---|---|---|
| `[MUST]` | 머지 전에 반드시 고쳐야 함. 버그, 보안, 규칙 위반, 완료 조건 미충족 | 수정하고 답글로 알린다 |
| `[SHOULD]` | 고치면 더 좋음. 가독성, 구조, 성능 | 반영하거나 안 하는 이유를 답한다. 후속 이슈로 넘겨도 된다 |

## 코멘트 형식
`[태그] 무엇이 문제인지 / 왜 문제인지 / 어떻게 고칠지`

예시:
> [MUST] 종목코드를 int로 읽어서 `005930`이 `5930`이 됩니다. 시세 API는 6자리 문자열 코드로 조회하므로 조회가 실패합니다. 문자열로 유지하고 숫자 6자리인지 검사해 주세요.

> [SHOULD] 중복된 종목코드가 그대로 반환됩니다. 수집 단계에서 같은 종목을 두 번 호출하게 되니 중복이면 ValueError를 내면 좋겠습니다.

## 리뷰 결과 선택
- `[MUST]`가 하나라도 있으면 **Request changes**
- `[SHOULD]`만 있으면 **Comment** 또는 **Approve**
- 수정을 확인하면 대화를 Resolve하고 **Approve**

## 체크리스트
- [ ] 이슈의 완료 조건을 모두 만족하는가
- [ ] 테스트가 추가됐고 CI가 통과하는가
- [ ] 워크플로 `permissions`가 최소 권한인가
- [ ] 토큰, 키가 코드나 로그에 노출되지 않는가
- [ ] PR 제목이 Conventional Commits 형식인가
- [ ] README 등 문서가 변경 사항과 맞는가

## Copilot PR 리뷰
- 리뷰 요약이나 코멘트에 `@copilot`을 넣어야 Copilot이 수정을 시작한다.
- Copilot이 푸시한 뒤에는 워크플로가 자동으로 돌지 않는다. **Approve and run workflows**를 눌러 CI를 실행한다.
